# RTL 编码与实现纪律

## 1. 可综合性底线

| 项 | 要求 |
|---|---|
| 语法子集 | 只用可综合子集；`initial`、`#delay`、`$display` 仅限仿真 |
| 锁存器 | 组合 always 块所有分支赋默认值，禁止推断 latch |
| 多驱动 | 一个信号只能在一个 always 块 / assign 中驱动 |
| 组合环 | 禁止组合反馈；需要"同步"就加寄存器 |
| 位宽 | 显式位宽，禁止隐式截断与符号扩展混淆 |
| 参数 | 参数默认值必须可直接综合；位宽由参数决定时不要在下层写死 |

## 2. 模块规范

- 一个文件一个模块，文件名 = 模块名
- 端口顺序固定：时钟、复位、配置、数据输入、数据输出
- 端口声明带方向、位宽、注释（用途 + 时钟域）
- 组合逻辑与寄存器逻辑分离；一个 always 块只描述一件事
- 参数化的东西：数据位宽、深度、实例数、地址宽度、功能开关（`generate` 而非注释掉代码）

## 3. 握手与流控

**valid-ready 铁律**
- valid 一旦拉高，在 ready 之前不得撤销，数据不得变化
- ready 可以依赖 valid（组合反压），但 valid 不得依赖 ready（会形成组合环）
- 有效载荷只在 `valid && ready` 那一拍被消费

**不要混用 credit 与 valid-ready**：两种流控拼在一条通路上，最容易出现"credit 归零但数据还在飞"的死锁。确实要级联，中间加一级 buffer 做解耦。

**反压传播**：每一级都要能反压上游。末端不可反压（如到 DRAM）时，必须有缓冲 + 丢包/背压策略，并写清溢出行为。

## 4. 跨时钟域（CDC）

| 场景 | 做法 | 禁区 |
|---|---|---|
| 单 bit 电平 | 两级同步器（异步复位同步释放同理） | 直接用异步信号做逻辑 |
| 单 bit 脉冲 | 脉冲展宽 + 同步器，或 toggle 握手 | 直接两级同步窄脉冲（可能漏采） |
| 多 bit 数据 | 格雷码（计数类）/ 异步 FIFO / 握手同步 | 多 bit 各自两级同步（位间偏斜） |
| 总线 | 异步 FIFO，指针用格雷码 | 直接跨域采样数据总线 |

**异步 FIFO 要点**
- 空满判断用格雷码指针，多打一拍对齐后再比较
- 深度取 2 的幂，便于指针回绕
- 满/空阈值留余量（至少 2 拍同步延迟）
- 复位时两侧指针都要归零，且复位释放顺序要明确

## 5. 复位

- 明确：同步还是异步、高有效还是低有效、复位域边界在哪
- 异步复位同步释放（reset synchronizer）是常态；只做一半（异步置位 + 同步释放漏掉）是经典缺陷
- 复位值必须与 spec 寄存器表一致，字面量直接对得上
- 数据通路可以不复位（配 valid 清零），但控制状态机必须复位
- 软复位 / 域复位要写清影响范围：复位后配置寄存器是否丢

## 6. 低功耗写法

- clock gating：用带 latch 的 ICG 单元，不要用与门直接切时钟
- operand isolation：无效计算前把输入锁住，减少翻转
- 状态编码：多 hot 或少 hot 看解码深度与翻转率权衡
- 无访问即关断：SRAM 使能按 bank/按行控制

## 7. 交付前的自检清单（手动过一遍，再上工具）

- [ ] 无 latch、无多驱动、无组合环
- [ ] 所有位宽显式，参数化位宽没被字面量写死
- [ ] 复位值与 spec 寄存器表逐条一致
- [ ] 状态机有 default 分支，且能从任意状态回到 IDLE
- [ ] 每个跨时钟域信号都有明确同步方案，CDC 工具无未确认告警
- [ ] 握手通路无组合环、无反压断点
- [ ] 未使用信号不悬空（输出悬空要接常量或标 unused）
- [ ] 关键路径预估延迟在目标频率内，超标处已标给后端

## 8. 交给验证的待验点

RTL 交付必须附带这份清单，否则验证只能靠读代码猜：

- 每个状态机的状态与转移覆盖要求
- 边界条件：空/满、溢出、超时、地址越界、非法配置组合
- 反压与背靠背场景
- 复位与恢复场景
- 已知不覆盖项及原因（比如依赖外部模型的路径）

## 9. Lint / CDC / RDC 报告怎么收

### 9.1 先分桶，别一条条改

四百条 warning 一条条修，改错的风险远大于收益。先按四桶分开：

| 桶 | 判据 | 处置 |
|---|---|---|
| **必修** | 位宽截断、隐式符号转换、latch 推断、多驱动、组合环、case 无 default 且有未定义输出 | 改代码 |
| **可豁免** | 有正当设计理由（如刻意用位宽截断做饱和、工具不认识的宏、黑盒边界） | 写 waiver + 理由 |
| **工具误报** | 工具不识别 generate 分支、参数化后实际不存在的通路 | 加 waiver，注释说明为何是误报 |
| **待确认** | 规则语义不清、依赖使用场景 | 挂起并指派责任人，不许沉默 |

归并同类项一次改完：位宽类、未使用信号类、敏感列表类、命名规范类。**同类一次改，不要逐条点。**

### 9.2 CDC 单独过，不和 lint 混

每条跨域必须回答三件事：**源时钟域 / 目的时钟域 / 同步方案**。回答不了就是未确认。

| 信号类型 | 合格方案 | 不合格 |
|---|---|---|
| 单 bit 电平 | 两级同步器 | 直接进组合逻辑 |
| 单 bit 脉冲 | 脉冲展宽 + 同步，或 toggle 握手 | 直接两级同步（可能漏采） |
| 多 bit 计数 | 格雷码 + 两级同步 | 各 bit 独立同步 |
| 多 bit 数据 | 异步 FIFO、握手同步、DMUX | 各 bit 独立同步 |
| 复位跨域 | 异步复位同步释放 | 各自域独立释放 |

**RDC（复位域交叉）容易被漏**：两个模块在同一时钟域但复位不同源，会出现一个模块已复位、另一个还在跑的窗口。检查清单里必须单独列这一项。

### 9.3 Waiver 要写成条目

```tcl
# [WV-017] rule: WIDTH_TRUNC  file: dma_engine.v:214
# 理由：此处刻意取低 12 位做环形缓冲索引，高位由 base addr 提供
# 责任人：<name>   复核条件：若缓冲深度改为非 2 的幂，此 waiver 失效
```

四个字段缺一不可：**规则 ID / 位置 / 理由 / 责任人 + 复核条件**。没有理由的 waiver 三个月后就没人敢动，也没人敢删，这是技术债的标准生成方式。

### 9.4 收口标准

不是"报告清零"，而是**每条剩下的都有据可查**：

- [ ] 必修桶清零
- [ ] 每条 waiver 有规则 ID、位置、理由、责任人
- [ ] CDC 每条跨域有源/目的域与方案标注，工具无未确认项
- [ ] RDC 单独过了一遍
- [ ] 与上一版相比，新增告警数量与原因已知（防止"越改越多"）

**红线**：为了清零而豁免功能相关的告警（位宽截断、case 未覆盖、多驱动），等于把缺陷藏进 waiver 文件。
