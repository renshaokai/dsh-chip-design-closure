# 设计评审与 spec↔RTL 对账清单

评审的产出是**可定位的结论**，不是观后感。每条 finding 必须有：位置 + 判定 + 证据 + 修法。

## 零、四条前置判据（先过这四条，再往下查细节）

文档质量不是"读起来清不清楚"，是下面四条能不能成立。任何一条不成立，后面的逐条检查都是在给一份用不了的文档挑排版。

| 判据 | 怎么验 | 不合格的表现 |
|---|---|---|
| **契约性** | 项目过程中有人因为 spec 与实现不一致而改设计或走变更评审吗？ | 从没有人被它挡过 → 它是描述，不是契约 |
| **约束力** | 从文档能唯一推回实现方案吗？两份不同的 RTL 都能满足它 → 太粗；能指到信号位选 → 太细 | 只写"三级流水"（太粗）或抄了语句（太细） |
| **可交接** | **作者不在场时还能用吗？** 让他人只看文档答：改这个信号谁受影响、从哪个文件开始读 | 答不上来 → 隐性知识没显性化 |
| **可裁决** | 抽查三处行为，只靠文档能判出"第几拍、哪个沿、什么条件下、值是多少"吗 | 只能跑仿真反推或去问作者 → 验证只能猜，猜错 50% 概率误判正确的 RTL |

**可裁决抽查法**：随便挑一条时序或功能结论，盖住代码问：现在 `valid` 拉高后第几拍 `ready` 该拉高？采样在哪个沿？前提配置是什么？三个答不全就是不合格。

**形式检查**（三条硬规矩，见 `spec-outline.md` 总则）：

- [ ] **表带前提**：每张表上方或表头写清了适用配置与时钟域，不是散落在正文段落里
- [ ] **承载取值的图配了表**：时序图 / 波形图（四列：拍号、信号、期望值、前提）、状态机转移、计算映射（并行度与复用）这四类必须有表
- [ ] **没给纯结构图造镜像表**：结构图、拓扑图配的是图里放不下的维度（职责 / 不做什么 / 责任人），不是把方框复述一遍——镜像表等于两份数据手工同步，必然漂移
- [ ] 图与表冲突时以表为准，且图已回改（不能留一张过期的图挂着当权威）
- [ ] **散文 ≤3 句**：解释性文字每节不超过三句（超了通常是该拆表，或决策没定）。**唯一例外**：状态机的跳转原理允许 3–5 句（四个问题各一句），职责一节允许"一句话 + 不做什么"
- [ ] **没有用散文写契约**："适当的时候反压""较快""若干拍"这类措辞一处都不许留
- [ ] 散文占篇幅超过三成的章节，单独说明为什么不能表格化（**这是提示，不是错误**——真正的判据是上一条"每节 ≤3 句"）

## 分级

| 级别 | 含义 | 例子 |
|---|---|---|
| 错误 | 功能必错或契约矛盾 | offset 重复、位域重叠、RTL 无此寄存器译码 |
| 警告 | 表述与实现不一致，行为可能等价但不可信 | spec 声明可写、RTL 未消耗该位 |
| 提示 | 可改进，不影响功能 | 未定义位区间、参数化位宽无法位级比对 |

## 一、Spec 自身检查

**结构**
- [ ] 七章齐备，裁剪已在**第 1 章 1.3（行文规范与裁剪登记）**记原因
- [ ] 无空章节（空章节比 TBD 更糟）
- [ ] 修订记录与版本号一致
- [ ] **修订记录有偏离登记**：实现阶段偏离过的地方，要么改了文档升了修订号，要么写了"偏离 X，原因 Y，待合入"
- [ ] 修订记录能回答"哪次提交对应哪一版文档"
- [ ] 已知过期做不到就地改的章节标了 `⚠ 已过期，见 vX.Y`，没有把过期内容当有效规范留着
- [ ] 每章有责任人（不只全文一个）
- [ ] **有 1.6 阅读路径**：写明不同角色先读哪章、哪几节必读
- [ ] **有代码地图**：模块 → 文件 → 建议先读哪个，交接时能直接上手
- [ ] 反向补的 spec，1.1 记了源 RTL 版本与提交号（否则无法回溯对的是哪版代码）
- [ ] **文档状态写的是 As-Built**，没有任何一处暗示它有契约效力
- [ ] 拆文档的粒度按判据走过（责任人/交付节奏/评审场合/版本演进），不是因为"子模块多"就拆
- [ ] 多模块单文档按 3.x 分节，模块六要素是六个三级标题而非散文；职责边界表（含"不做什么"）先写
- [ ] 多份 spec 汇总成系统级时按横向维度组织，不是按子模块分章装订

**取证与出处**
- [ ] 每个可验证结论都有出处（源码引用 / 协议章节号 / 决策编号）
- [ ] 寄存器表 evidence 列真填了，不是照抄 attr 或留空
- [ ] 接口表 evidence 列能指到端口声明行
- [ ] 出现"最多 N 拍""深度 ≥ M"这类数字，同句标了推导还是保证，并写明前提
- [ ] 附录 E 非空——空着的反向 spec 几乎一定没查，而不是真没有
- [ ] 正文里的 `(RTL 未明确)` 标记与附录 E 条目对得上

**功能与接口的三态判定**
- [ ] 功能表用 `已实现 / 条件支持 / 暂不实现`，没有自造取值
- [ ] `条件支持` 项写清了具体参数、宏或输入取值
- [ ] 只有参数声明或 generate 框架、无实际数据通路的，没标"已实现"
- [ ] 端口存在但不被消费的，description 写明未参与功能，且进了附录 E
- [ ] **第 6 章没有越界到验证计划**：没写 UVM 环境结构、覆盖率目标百分比、回归流程、sequence/testcase；这些归验证侧
- [ ] 第 6 章写了"本章不包含什么"（边界声明），或至少能力边界一节覆盖了
- [ ] 正向 6A 与反向 6B 没有同时出现（二选一）

**寄存器表**
- [ ] **所有 offset 是绝对地址**，不是每个模块都从 0x000 起（否则驱动要自己拼地址，且机器判不出冲突）
- [ ] 段分配表齐全：段不重叠、不跨界，余量写明用途，外部 IP 的段标"外部交付"不展开明细
- [ ] 分模块明细是主表按模块的切片，不是第二张表（每行仍绝对地址、列一个不少）
- [ ] 明细表与汇总表集合一致（缺的、多的都是缺陷）
- [ ] 同 offset 命名一致（`CURDES_MSB` vs `CURDESC_MSB` 这种少一个字母的最常见）
- [ ] 标题声明的 offset 与表内一致
- [ ] lsb ≤ msb，msb < 位宽
- [ ] 位域不重叠
- [ ] 非 Reserved 位域有 attr 与 reset
- [ ] 位域 reset 合成 = 寄存器 reset
- [ ] offset 4 字节对齐、无重复
- [ ] 附录 A 不是手抄的第二份主表（同一张表两份手工维护必然漂移；无生成流程时宁可不设附录 A）

**接口表**
- [ ] 位宽是数值或明确参数名+默认值，不是 `N`
- [ ] 参数化位宽按三段式写：参数名（不是表达式）+ 文档内闭式定义与取值表 + 至少一个配置点的实际位宽
- [ ] 协议接口除信号表外有通道表（方向/位宽/outstanding 深度），outstanding 的算式写在同一节
- [ ] 每个信号有时钟域
- [ ] 协议接口按通道分组完整（AXI 的 AW/W/B/AR/R 五通道）
- [ ] 复位信号写清极性与同步方式

**模块章节**
- [ ] 六要素齐备（职责/端口/时序/状态机/实现/异常）
- [ ] 状态机闭环：无死路、任意状态可达 IDLE
- [ ] 时序契约有拍数，不是"较快"
- [ ] 时序契约标了 M/R/X 级别（全 R 说明没人真用过这张表）
- [ ] **状态机写了跳转原理**：为什么拆成这几个状态、为什么不合并、中间态存在的理由、哪个态是性能瓶颈——只有跳转表没有这几句，划分是否合理无从判断
- [ ] 多条件同时成立时**谁优先**写了（不能靠 always 块顺序）
- [ ] **每个控制信号给了复位后初值**，不是一句"复位清零"

**实现方式（最常写成一句话，逐项查）**
- [ ] 数据通路四要素齐：传输 / 计算 / 保存 / 控制
- [ ] **传输写了生命周期**：进 buffer 后谁释放、credit 怎么回收、指针回绕怎么处理（只写路径不算写完）
- [ ] **有算子表**：算子 → 硬件资源 → 复用次数 → 并行度 → 每拍产出 → 依据
- [ ] 算子表的复用次数 × 并行度能倒推回架构预算（不成立说明方案与预算脱节）
- [ ] **有资源账**：类型 / 深度 / 位宽 / bank / 端口 / 用途 / 冲突仲裁；有 ECC 的写了纠检能力
- [ ] **有精度口径**：累加位宽及其依据、截位还是饱和、舍入方式、定点位置
- [ ] 没写语句级内容（`if (cnt == 4'd7)`、三段式/两段式、信号前缀）——那是实现自由度

**决策与可观测性**
- [ ] **有决策台账**：决策 / 备选 / 理由 / **失效条件**，失效条件一列无空
- [ ] 决策台账能解释"为什么不选另一个方案"，不是只记结论
- [ ] **有内部状态 → 可观测出口映射表**，且明确写出了哪些"看不见"
- [ ] 看不见的内部状态，给了间接推断路径（否则验证只能去驱动内部信号）

## 一·B、反推稿专项检查（只对 RTL → spec 的产物）

**先定档位**——问一句"读完这份文档的人敢不敢改这段 RTL"。敢 → 该按交接档查；只需驱动/集成/验证用 → 归档档就够。**拿交接档标准去挑归档档的毛病，或者反过来，都是错位的评审。**

**档位与骨架**
- [ ] 明确说了这是归档档还是交接档
- [ ] **七章齐备，没有删章**（删了就没法与正向文档并排比对，也没法增补成交接档）
- [ ] 没有空章节；每个 `不适用` 给了理由，每个 `TBD` 指到了问题编号
- [ ] 交接档的第 3 章写到了 3.a 四要素 / 算子表 / 资源账 / 精度口径；归档档压缩了但没有缺 3.c 与 3.d
- [ ] 状态写的是 As-Built，或已签发（此时须有签发人、日期、版本号）

**问题清单（无设计者可问时是必查项）**
- [ ] 问题清单在文首附近，不是埋在附录末尾
- [ ] **每条都有"本版默认判断"**——只提问不给判断的，等于把工作推回给读者
- [ ] 级别三档门槛一致：阻塞 / 重要 / 记录；阻塞项没有滥用（满篇阻塞等于没分级）
- [ ] 文首声明了证据状态：RTL 反推、未经确认、N 条阻塞未解决
- [ ] 正文 `[?Q-xx]` 与清单双向能对上；已答复条目保留了记录并标了版本

**读感与人改友好度**
- [ ] 正文顺序跟数据流（输入→处理→输出→异常），不跟代码文件顺序
- [ ] 篇幅按分级分配，**没有出现"每节都三段"的均匀用力**
- [ ] 追溯信息全在 evidence 列或脚注，正文没有夹源码位置
- [ ] **复述测试做过**：非本人复述不出现信号名，说得出"为什么需要这个模块"
- [ ] 审核能按固定顺序走：问题清单 → 功能表粒度 → 寄存器/接口数值 → 决策理由

**名字与代码痕迹**
- [ ] 正文无内部信号名；`snake_case` 白名单扫描通过（未解释的内部名 ≤5）
- [ ] 1.2 术语表建了概念名 ← 真实名的映射
- [ ] 只有三处允许的代码：参数化位宽公式、位域拼接、状态编码值
- [ ] 无 always 块片段、无赋值语句、无源码行号混在正文

**功能点粒度（反推稿最容易错的地方）**
- [ ] **先抛开 RTL 列过功能候选**，不是直接按代码结构列
- [ ] 每条都过了三问：外部可观察 / 实现无关 / 可独立判对错
- [ ] FP 数量落在 10–40 条（中等模块），出区间的正当理由写在 1.3
- [ ] 没有实现方式混进功能表（"用 8 级 FIFO"、"状态机 5 个态"、"计数器加 1"）
- [ ] 命名是"动词 + 对象 + 条件"，没有模块名、没有"支持 AXI4"这类装了多个功能的粗条
- [ ] **功能表列结构与正向文档相同（6 列）**，出处进 evidence 列，没有反向专用列
- [ ] 代码里没实现的候选（功能缺口）进了问题清单，没有悄悄丢掉

## 二、Spec ↔ RTL 对账

**寄存器**
- [ ] spec 中每个可写寄存器地址，RTL 写入译码里都有（`case (wr_addr)` 逐项比）
- [ ] spec 声明可写的位，RTL 真的消耗了对应 `wr_data` 位
- [ ] 只读寄存器 RTL 不写（写了要注意读回是否被掩码）
- [ ] 复位值字面量与 RTL `if (!rstn)` 分支一致；参数化复位要单独说明
- [ ] RTL 可写但 spec 未声明的地址 = 未声明写，属警告

**接口**
- [ ] 端口名全集一致（spec 多出的 = 缺失，RTL 多出的 = 未声明）
- [ ] 方向一致
- [ ] 位宽一致；参数化位宽按模块参数默认值求值后比较
- [ ] 时钟域归属一致（RTL 里跨域的端口，spec 要标同步方案）

## 三、RTL 代码审查

- [ ] 无 latch / 多驱动 / 组合环
- [ ] 位宽无隐式截断；比较两侧位宽一致
- [ ] 复位覆盖：控制状态机全复位，数据通路有 valid 清零
- [ ] 异步复位同步释放完整（不只是异步置位）
- [ ] 跨时钟域全部有同步方案，无多 bit 各自两级同步
- [ ] 异步 FIFO 空满判断用格雷码且对齐全拍
- [ ] 握手无组合环（valid 不依赖 ready）
- [ ] 计数器/指针回绕处理正确
- [ ] `default` 分支存在，异常地址有响应（AXI 需返回 SLVERR/DECERR）
- [ ] 参数默认值可直接综合，顶层没把参数写死

> 综合与时序报告的审查项见 `synthesis-timing.md`（报告读法、违例五分类、收敛判据）；面积功耗优化建议的写法见 `ppa-optimization.md` 第 5 节；集成期契约（地址表、outstanding、域图、中断、低功耗件）的逐条核对见 `soc-integration.md` 第 7 节。收敛类评审的判断标准和文档类不同：它不看章节齐不齐，看**每条违例是否有分类和处置**。

## 四、集成契约对账（顶层与子系统之间）

- [ ] 契约矩阵齐全（源/目的/信号组/方向/位宽/协议/拍数/反压），**每行的拍数标了 M/R/X 级别**
- [ ] 矩阵里不是所有行都在 R——全 R 说明没人真用过这张表
- [ ] 地址表与译码器 `case`/比较项逐条对得上，**无空洞、无重叠、有 default slave 回 DECERR**
- [ ] 每个 slave 的 base 按 size 对齐，size 是 2 的幂
- [ ] spec 写的 outstanding 深度与实际例化的 buffer 深度一致；深度有算式来源
- [ ] 4 KB 边界由谁拆已明确，且该模块确实实现了拆分
- [ ] 时钟域图上每个跨域点在 RTL 里都能找到同步器实例（反过来也要查：RTL 有同步器但图上没标 = 未登记）
- [ ] 复位按源分组后，跨组通路都有隔离件
- [ ] 中断表里每个源在 RTL 里都有 status 位，且 mask 位置在聚合前
- [ ] `W1C` 实现为 `status & ~wr_clear`，不是 `status <= 0`
- [ ] 每个可关断域的输出都有 isolation，默认值给的是"无效"
- [ ] 关断流程里有"等 outstanding 事务返回"这一步
- [ ] 跨电压域有 level shifter，位置表已交后端

## 五、FP / VP 检查（验证基线专项）

交付给验证之前逐条过。参考 `references/fp-vp-generation.md`。

**功能点**
- [ ] FP 按章节分组、按功能合并，**不是按寄存器字段或实例个数数出来的**
- [ ] 每个 FP 能答出：编号 / 名称 / 行为概述 / 依据条款 / 分级 / 证据等级
- [ ] 通用检查（复位、接口时序、时钟域）单独成 FP，没有散进各功能
- [ ] 分级齐备（P0 基础运行 / P1 完整功能 / P2 边界完善），无未分级项
- [ ] 逐条反查：每条条款至少进了一个 FP，无漏网条款
- [ ] 反向文档的 FP 标了 `measured` / `inferred` / `tbd`

**测试点**
- [ ] VP 写清了改变的条件、激励、预期结果、检查位置、依据
- [ ] 预期结果落在具体采样边沿，不是"应该会变"
- [ ] 顺序敏感、边界值、并发三类拆开，没有合进一条
- [ ] 合并的 VP 前提/预期/驱动观察/检查方式/执行类型全一致
- [ ] 顶层类 VP 写清了"从哪个端口进、经哪条连接、到哪个输出"，没有用"直接驱动内部信号"描述
- [ ] 同类多实例分别列了 VP，且查了串扰
- [ ] 顶层看不到的信号，写明了预期观察点位置（具体用监视器还是断言是验证侧的实现选择）

**交付声明**
- [ ] 写了覆盖范围与未覆盖项
- [ ] 写了 P0/P1/P2 分布及哪些 P0 尚未有 VP（**不是"未实现用例"**——用例归验证侧）
- [ ] 列出了 `inferred` / `tbd` 的 FP
- [ ] 附录 E 的限制逐条对应到"哪些行为无法给预期结果"
- [ ] 写明能力边界：可作回归基线与改动影响分析，需求正确性判定不来自本文档

**边界（不越界到验证环境）**
- [ ] 清单里的断点检查全部是文档自洽，没有一项依赖跑仿真或读覆盖率报告
- [ ] 没有承诺 sequence/test/coverage bin 的产出，也没有评价验证环境结构
- [ ] 追溯止于 VP，并写明了"编号/分级/预期结果"是交给验证侧建 bin 与用例的输入

## 明细

## 七、五个容易犯的评审错误

1. **用字数判断"写清楚了"**。实测：47 个有章节的子模块里端口表 0 个、时序数值 1 个，但正文和图都不缺——缺的是结构化契约。查表，别数字。
2. **只报"不通过"不给证据**。评审的价值在于"翻到第几章第几张表能自己核对"，没有位置的结论无法闭环。
3. **把推断当事实**。从 RTL 反推的接口协议类型、时钟域归属、模块职责都是 `inferred`，必须标出来让人确认，不能混进 `measured` 一起交付。
4. **把附录 E 空着当优点**。反向 spec 的限制项一条不写，通常不是查干净了，而是没往这个方向查。先抽查两个未被消费的端口，看附录里有没有——没有就退回。
5. **在散文里放过模糊词**。"适当的时候""较快""基本上""若干拍"——这些词在散文里读着通顺，就是契约还没形成的地方。逐条挑出来要求给出数值与条件，比通读三遍有效。

## 八、功能是否真存在（反向 spec 专项）

反推文档最容易在这一步失真。对每条标"已实现"的能力，问三句：

1. **赋值在哪？** 指不出一行实际赋值、状态更新或例化连接的，降为"条件支持"或删掉。
2. **条件是什么？** 只在某参数/宏下成立的通路，写清取值；写不清就是没查透。
3. **谁能用？** 端口声明了但下游无引用，等于不可用。按名字当成可用能力写进文档，是集成阶段返工的主要来源。
